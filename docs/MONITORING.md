# 更新监控模块设计（v1.2.9）

## 一、需求拆解

围绕「关注的游戏 / Mod 是否有更新」提供一条从**检测 → 提示 → 人工一键订阅 → 规则自动订阅**的完整链路，并与既有领取、工坊、通知、总览体系打通。

### 1. 监控对象
- **游戏本体（商店信息）**：关注某 AppID，监控商店详情指纹是否变化（名称、价格、DLC 清单、发行日期、封面、支持语言）。
- **游戏工坊**：关注某 AppID 的创意工坊，监控最近更新 / 新上架 Mod。
- **指定 Mod**：按 Published File ID 关注单个 Mod，监控其 `time_updated` / 文件大小变化。

### 2. 检测与提示
- 手动「立即检测」+ 后台定时自动巡检（间隔可配，默认关闭）。
- 每次检测把变化写入本机事件流（游戏更新 / Mod 更新 / 新 Mod / 规则命中），未读计数在总览与监控页提示。
- 完成后复用既有 Webhook 通知通道。

### 3. 订阅与规则
- 事件流 / 关注 Mod 列表支持一键订阅（复用既有浏览器登录态与拟人节奏）。
- 关键字规则：按 AppID（可空 = 任意游戏）+ 关键字（任一 / 全部命中）匹配标题与标签；命中且开启自动订阅时，自动进入订阅队列。

## 二、数据源与能力边界（诚实标注）

| 信号 | 来源 | 说明 |
|---|---|---|
| Mod 更新时间 / 大小 / 标题 / 标签 | `IPublishedFileService/GetDetails/v1` | 需 Web API Key，只读，无需浏览器登录态 |
| 工坊最近更新 / 新上架列表 | `IPublishedFileService/QueryFiles/v1`（按最近更新排序） | 需 Web API Key，分页游标 |
| 本体商店信息指纹 | 商店 `appdetails` | 复用既有缓存与降级链路 |

**已知边界（Steam 公开接口不提供，不做虚假承诺）：**
- 商店公开接口**不暴露游戏可执行文件的版本号 / 补丁号**。本体「版本」以商店信息指纹变化为准；若需精确补丁版本，需后续接入非官方数据源或读取本地安装清单，本期不做。
- 本体更新的「补丁内容」无公开变更日志接口，事件仅标注「商店信息有变化」。
- 自动订阅仍走浏览器登录态（Cookie）；只读监控走 Web API Key，两条链路相互独立。
- 关键字匹配基于标题与标签文本，不做语义理解。
- 首次关注某游戏时只建立工坊基线，不把当前首屏 Mod 误报为「新上架」；下一次检测起才对比出新增 / 更新。

## 三、数据模型（本机 SQLite，不上传）

- `watch_games`：关注的游戏（本体 / 工坊开关、上次指纹、上次工坊快照、最近检查时间）。
- `watch_mods`：关注的 Mod（fileid、appid、标题、封面、上次更新时间 / 大小、订阅标记）。
- `watch_rules`：关键字自动订阅规则（appid=0 表示任意、关键字、匹配模式、自动订阅开关、启用开关）。
- `watch_events`：更新事件流（类型、对象、标题、详情、检测时间、已读标记、动作）。

## 四、联动与顺手性

- 监控发现的 Mod 一键订阅 → 复用工坊浏览器链路与限速 / 冷却。
- 总览仪表盘汇总未读监控事件数，点击直达监控页。
- 检测结果写入软件内日志；完成通知复用既有 Webhook。
- 监控目标、规则、事件全部本机留存，卸载 / 清空不影响 Steam 账号侧状态。

## 五、隐私

- 监控仅保存 AppID / FileID / 标题 / 标签等公开元数据；Web API Key 只存本机设置，不下发前端、不进产物。
- 测试使用占位 ID 与保留域名，不写入真实凭证。
